Overview

Design rationale

Who this system is for and the reasoning behind each decision. Agents must use these tokens and components — never guess a color, font, spacing or radius.

Tokens→Atoms→Molecules→Organisms→Templates→Pages

Audience

Professionals using dense, data-heavy screens under time pressure; also teams who need a neutral base to re-skin per client.

Why it looks like this

Color

A graphite near-black primary gives maximum contrast and zero brand bias, so status colors and charts carry all the meaning. A single blue tertiary is kept for links, focus and selection. This is also the safest starting point for /designku:ds-customize.

Typography

IBM Plex Sans has an engineered, technical voice with distinct glyphs for I, l and 1; IBM Plex Mono for IDs and codes.

Shape and density

Sharp 4-8px corners and compact density read as professional tooling and maximize data per screen.

Motion

Snappy and functional only.

Do / Don't

  • Use tertiary (blue) for links, focus rings and selected rows; primary (graphite) for the main button.
  • Encode status with color + icon + label; this system is designed for many status chips.
  • Use the mono family for identifiers, codes and aligned numeric columns.
  • Do not introduce new accent colors per feature; extend tokens.json if a category color is truly needed.
  • Do not use elevation for static cards — use outlineVariant borders.
  • Do not reduce row height below size.listItem to fit more data.
